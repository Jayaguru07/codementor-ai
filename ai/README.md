# CodeMentor AI — LLM + RAG AI Module

Welcome to the **CodeMentor AI** AI module. This project is an intelligent programming debugging and learning assistant built using **Retrieval-Augmented Generation (RAG)** and **Cloud Large Language Models (LLMs)**.

---

## 1. Core Architecture & Pipeline

```text
Student Submission
(Code + Language + Error)
         │
         ▼
  Query Synthesis (rag.py)
  [Isolates localized error lines for large codebases]
         │
         ▼
  Embedding Model (all-MiniLM-L6-v2)
  [Converts text into normalized 384-dimensional dense vector]
         │
         ▼
  FAISS Similarity Search (IndexFlatIP)
  [Computes exact cosine similarity against indexed knowledge]
         │
         ▼
  Top-K Relevant Knowledge Chunks
  [Retrieved from ai/knowledge/ (Python/Java/DSA)]
         │
         ▼
  Prompt Construction (prompts.py)
  [System Mentor Prompt + Knowledge Context + Student Code]
         │
         ▼
  Cloud LLM API (_call_chat_completion)
  [OpenAI, Groq, OpenRouter, Together AI via HTTP]
         │
         ▼
  Structured JSON Output
         │
         ▼
  Pydantic Validation (CodeAnalysisResult)
         │
         ▼
  FastAPI Backend (Future POST /api/analyze)
         │
         ▼
  Web Frontend
```

## 2. Viva Essentials — Key Concepts Explained Simply

When explaining this project in a viva or technical interview, use these concise definitions:

| Term | Viva Definition |
|---|---|
| **Embedding** | A numerical vector (e.g. 384 numbers) that captures the semantic meaning of text. Semantically similar concepts map to nearby coordinates in vector space. |
| **Embedding Model** | A specialized neural network (here: `all-MiniLM-L6-v2`) that encodes text into vectors. It **only embeds**, it **does NOT generate text**. |
| **Vector Database** | A specialized database or indexing library that stores numerical vectors and performs fast geometric similarity searches. |
| **FAISS** | Facebook AI Similarity Search — an ultra-fast, lightweight library for searching high-dimensional vector spaces. |
| **RAG** | Retrieval-Augmented Generation — an architecture that fetches trusted external documentation from a vector database and provides it as context to the LLM before answer generation. |
| **LLM** | Large Language Model (e.g., GPT-4o-mini, Llama 3.1) — a generative neural network that receives the prompt + retrieved context and produces natural-language explanations and corrected code. |

### Critical Viva Distinctions:
- **`Embedding Model != LLM`**: The embedding model converts words into numbers for searching. The LLM converts prompts into natural language explanations.
- **`FAISS != LLM`**: FAISS is a search index for vectors; it contains no language intelligence and cannot write or debug code.
- **`RAG != LLM`**: RAG is the **entire end-to-end pipeline** (Ingestion -> Vector Search -> Prompt Augmentation -> Generation).

## 4. What Each File Does

### `ingest.py` (Ingestion Pipeline)
- **Runs offline** whenever knowledge files change (not on student queries).
- Discovers all `.md` and `.txt` files in `knowledge/`.
- Splits documents into **word-based chunks (~150–250 words)** with **sliding overlap (~30–50 words)**.
- Generates 384-dimensional vectors with `sentence-transformers/all-MiniLM-L6-v2`.
- Normalizes vectors ($L_2$ norm) and builds a `faiss.IndexFlatIP` index.
- Persists the index to `vector_store/index.faiss` and metadata to `vector_store/metadata.json`.
- **Idempotent**: Re-running safely rebuilds the store without duplicate vectors.

### `rag.py` (Retrieval Engine)
- Implements `RAGEngine` with **lazy loading**: embedding model and FAISS load only on the first retrieval call.
- Validates that `len(metadata) == index.ntotal`.
- **Large Code Handling**: Implements `_synthesize_query()` to handle 5 operational cases:
  - **Case A**: Small code + error -> uses full snippet.
  - **Case B**: Large code + error -> extracts localized error lines.
  - **Case C**: Large code + traceback -> regex matches traceback line numbers and extracts a $\pm 3$ line window.
  - **Case D**: Large code without traceback -> extracts primary function headers and logic.
  - **Case E**: Code with no error message -> formats general review query.
- Computes **cosine similarity** via inner product on normalized vectors ($\text{score} \in [-1.0, 1.0]$).

### `prompts.py` (Prompts & Schemas)
- Defines the structured Pydantic schema: `CodeAnalysisResult`:
  - `error_type`: String category.
  - `explanation`: Student-friendly explanation.
  - `cause`: Exact root cause.
  - `concept`: Programming concept.
  - `corrected_code`: Clean minimal fix.
  - `learning_tip`: Practical takeaway.
  - `practice_question`: Targeted question.
  - `sources`: `List[SourceItem] = Field(default_factory=list)`.
- Defines `CodeAnalysisRequest` for input validation (rejects empty language/code).
- Formats system instructions enforcing educational pedagogy and strict JSON output.

### `llm_service.py` (Cloud LLM Client)
- Isolated cloud HTTP client (`_call_chat_completion`) communicating with any OpenAI-compatible API (`https://api.openai.com/v1`, Groq, OpenRouter, Together AI).
- Extracts JSON from LLM outputs, even if wrapped in markdown code fences.
- Validates output against `CodeAnalysisResult` with Pydantic.
- Attaches retrieved sources and similarity scores.
- Comprehensive error handling: missing API key, timeouts, network failures.

### `main.py` (CLI Test Runner)
- Standalone demonstration runner.
- Executes the primary demo scenario:
  ```python
  numbers = [10, 20, 30]
  print(numbers[5])  # IndexError: list index out of range
  ```
- If `LLM_API_KEY` is not set: runs and displays RAG retrieval without crashing, explaining how to configure `.env`.
- If `LLM_API_KEY` is set: executes full LLM analysis and displays formatted results.

## 5. Step-by-Step Setup & Usage

### Step 1: Install Dependencies
Create and activate a virtual environment, then install requirements:
```bash
# Windows
python -m venv venv
venv\Scripts\activate

# Linux / Mac
python3 -m venv venv
source venv/bin/activate

# Install required packages
pip install -r ai/requirements.txt
```

### Step 2: Configure Environment Variables
Copy the example environment file and add your cloud API key:
```bash
# Windows
copy ai\.env.example ai\.env

# Linux / Mac
cp ai/.env.example ai/.env
```
Open `ai/.env` and enter your credentials:
```env
LLM_API_KEY=sk-...your-real-key-here...
LLM_MODEL=gpt-4o-mini
LLM_BASE_URL=https://api.openai.com/v1
```
*(You can also use Groq: `LLM_BASE_URL=https://api.groq.com/openai/v1` and `LLM_MODEL=llama-3.1-8b-instant`)*.

### Step 3: Build the Vector Store (Ingestion)
```bash
python ai/ingest.py
```
*Output: Loads markdown files, creates overlapping chunks, embeds with all-MiniLM-L6-v2, and writes `ai/vector_store/index.faiss` and `metadata.json`.*

### Step 4: Run the Standalone Demonstration
```bash
python ai/main.py
```

### Step 5: Run Automated Tests
```bash
pytest ai/tests/ -v
```

## 6. RAG Evaluation

### Why Retrieval Quality Matters
An LLM can only explain what it receives. If the retrieval engine returns unrelated documents (e.g. returning "Variables" when the error is an "IndexError"), the LLM may become confused or hallucinate. Evaluating retrieval quality ensures that our vector database reliably matches the student's problem to the right concept.

### Sanity Evaluation Suite (`ai/tests/test_retrieval_quality.py`)
We evaluate retrieval quality across 5 standard student debugging queries:
1. **List Indexing**: `numbers[5]` on a 3-element list -> verifies `indexing.md` is retrieved with keywords like `index`, `list`, `range`.
2. **Undefined Variable**: `print(y)` -> verifies `variables.md` is retrieved with `NameError` / `variable` keywords.
3. **Zero Division**: `10 / 0` -> verifies `exceptions.md` is retrieved with `ZeroDivisionError` / `exception` keywords.
4. **Loop Bounds**: `range(len(items) + 1)` -> verifies `loops.md` is retrieved with `loop` / `range` / `off-by-one` keywords.
5. **Function Scope**: accessing a local variable outside a function -> verifies `functions.md` is retrieved with `function` / `scope` keywords.

### Scope of the Evaluation
This is a **retrieval sanity check**, not a formal benchmark. It verifies that:
- Top-$K$ results are returned and sorted descending by similarity score.
- Returned chunks are non-empty and point to valid knowledge documents.
- Expected conceptual keywords appear in the top-ranked text.

In future phases, the team can expand this into a quantitative benchmark (e.g., Hit Rate@K and Mean Reciprocal Rank (MRR)) with a larger test dataset.

## 7. Future FastAPI Integration

The AI module is designed for clean import into the future FastAPI backend (`POST /api/analyze`):

```python
# In backend/main.py (Future integration)
from fastapi import FastAPI, HTTPException
from ai.prompts import CodeAnalysisRequest, CodeAnalysisResult
from ai.llm_service import llm_service

app = FastAPI(title="CodeMentor AI API")

@app.post("/api/analyze", response_model=CodeAnalysisResult)
async def analyze_code_endpoint(request: CodeAnalysisRequest):
    try:
        result = llm_service.analyze_code(
            language=request.language,
            code=request.code,
            error_message=request.error_message,
        )
        return result
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))
```

## 8. Security & Guardrails

- **Zero Code Execution**: Student code is **strictly analyzed as text**. The system never calls `exec()`, `eval()`, `os.system()`, or `subprocess` on student submissions.
- **Zero Hardcoded Secrets**: All credentials reside exclusively in `.env`, which is listed in `.gitignore` and never committed.
- **Cloud-Only Generative LLM**: No Ollama or local multi-gigabyte models are required. The only local model is the 80MB embedding model `all-MiniLM-L6-v2`.
